# Context Compiler V0 preregistration

Status: sealed before compiler implementation

Selection timestamp: 2026-07-30T03:03:25Z

Base repository commit: `e140fd00cbcf59b6cace5632ecb29d46d0151a42`

This protocol tests one bounded question: can a deterministic, local TypeScript/
JavaScript context compiler cover at least 90% of a frozen provisional
required-context oracle, materially reduce disclosure versus complete changed
files, remain fast, and reuse the existing Share capture, scanner, airlock,
archive, and validator without changing Share Format cut 1?

The compiler proposes. The human disposes. Passing this protocol is not a
release decision or evidence of human product acceptance.

## Frozen scope

- Fifteen merged pull requests from four public MIT-licensed repositories.
- Six multi-file features/fixes, three public-interface changes, three
  configuration or persistence changes, two security-adjacent changes, and one
  symbol move/deletion.
- TypeScript and JavaScript analysis only.
- Current worktree, staged, and `A..B` Git diff inputs.
- Definition, depth-one dependency, depth-one consumer, convention-based test,
  and bounded instruction channels.
- Existing CLI selections and capture path only.
- Existing Share Format, scanner, airlock, archive, and validator only.
- Binary keep/drop of complete detected symbol ranges.
- No automatic test execution or redaction.

The following are excluded: GitHub/issue ingestion in the product, hosted or
browser changes, tree-sitter, language servers, compiler APIs, AST libraries,
call graphs, graph depth above one, LLMs, embeddings, semantic indexes, vector
stores, model or network calls, non-TS/JS analysis, new Share item kinds,
`cut: 2`, and Share Format changes.

## Corpus rule

`corpus.json` is the source-free frozen manifest. Accepted patches are defined
by the landed merge/squash commit and its first parent, not by GitHub's mutable
closed-PR `base.sha`. Changed paths were verified from those immutable pairs.
PR descriptions retain the substantive, task-defining text; repository
checklist boilerplate is excluded. Review references are public inline human
review comments. No comment is labelled as a human oracle when its text says it
was generated by an agent.

The repository-size criterion is approximate, not a post-hoc filter. Counts are
tracked files with `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, or
`.cjs` extensions on the selection date. Hono and Prettier sit near the soft
lower and upper edges and are retained because they supply genuine reviewed
security and parser changes; this exception is frozen before compiler output.

No task may be replaced after compiler output is observed.

## Frozen provisional oracle

The oracle is evidence-backed and contains no invented human label. It is
derived independently from each immutable accepted patch before scoring:

1. Every TS/JS changed hunk maps to its complete enclosing detected symbol.
   If conservative delimiter matching cannot prove a symbol boundary, the
   post-image whole file is the oracle fallback. Deleted hunks are represented
   by the complete diff and recorded as uncertainty when no post-image exists.
2. Every repository path or symbol explicitly named in a substantive frozen
   human review reference is an obligation. Retracted or explicitly corrected
   review claims are recorded but not promoted to obligations.
3. Changed tests, fixtures, and configuration that provide accepted-patch
   evidence are obligations. Generated snapshots and lockfiles are represented
   by their non-generated test/config counterpart and are not independent
   disclosure obligations.
4. Missing evidence is uncertainty, not a fabricated label. In particular,
   `operational-evidence` is unsatisfied unless the caller supplies command
   evidence.

Non-TS/JS changed material remains visible in the complete diff but receives no
synthetic symbol label.

## Frozen interpretation and obligations

Task interpretation proceeds in this order:

1. exact repository-relative paths in task text;
2. identifier-like terms intersected with normalized changed-symbol terms;
3. the fixed intent lexicon `review/security/audit`,
   `test/failing/repro`, `migrate/schema`, and `performance`;
4. otherwise `interpretation: diff-only`.

Only observed facts create obligations:

| Obligation | Base weight | Creation rule |
| --- | ---: | --- |
| implementation | 100 | every TS/JS changed-hunk enclosing symbol |
| public-interface | 8 | changed detected export |
| direct-consumer | 6 | at least one non-hub depth-one importer exists |
| test | 5 | a convention-based test references changed material |
| configuration | 5 | accepted patch or reference touches configuration |
| data-migration | 7 | accepted patch touches a migration path |
| operational-evidence | 4 | always; satisfiable only by supplied evidence |
| security-sensitive | 10 | auth/session/token/permission/crypto fact observed |

The fixed lexicon may raise a matching non-implementation weight by 2; it never
creates an otherwise unsupported obligation. Implementation obligations are
mandatory regardless of budget.

## Frozen candidate bounds

- Graph depth: exactly one and not configurable.
- Dependency candidates: 25 maximum.
- Consumer candidates: 25 maximum.
- Test candidates: 10 maximum.
- Instruction candidates: 3 maximum.
- Total candidates: 120 maximum.
- A module with more than 20 repository importers is a generic hub and is
  excluded from consumer selection.
- Compilation wall-clock ceiling: 3 seconds.
- Default estimated-token budget: 25,000.
- Generated, vendored, built, ignored, minified, snapshot, lockfile, and
  credential-like material is denied by default.
- Git ignore checks use one NUL-delimited
  `git check-ignore --no-index -z --stdin` batch.

Relative import resolution attempts `.js` source specifiers to `.ts`, TS/JS
extensions, index files, and one-hop basic re-exports. Path aliases, workspace
package imports, dynamic imports, conditional exports, and unresolved barrel
chains are reported, not guessed.

## Frozen selector

Mandatory implementation candidates are selected first. Remaining candidates
use deterministic greedy weighted set cover:

`score = sum(weight of uncovered satisfiable obligations) / sqrt(estimated tokens)`

Ties break by channel priority
`definition < dependency < consumer < test < instruction`, then
repository-relative path, then start line. Enumeration order and hash-map order
are never tie-breakers.

Token estimates are:

`ceil(max(UTF-16 code units / 4, non-whitespace lexical runs * 1.3))`

They are labelled estimates and are not tied to a model tokenizer.

## Arms and accounting

- A — complete accepted unified diff only.
- B — the complete accepted diff plus complete post-images of all non-deleted
  changed files, with identical blobs counted once.
- C — the complete accepted diff plus compiler-selected excerpts/files and
  their disclosed context halos, with identical blobs counted once.
- D — full-repository agent exploration with a fixed 20-tool-call budget.

Arm D and task-completion outcomes are observational. They may be recorded as
not evaluated; no values may be fabricated.

For A-C, count estimated tokens, bytes, files, excerpts, sensitive findings,
and oracle obligations covered. Reduction is `B estimated tokens / C estimated
tokens`. Required-context recall is covered oracle obligations divided by all
non-uncertain oracle obligations. Changed-hunk symbol coverage is reported
separately and must be 100%.

Every task is compiled twice. Normalized replay identity removes wall-clock
timestamps, absolute repository paths, and measured timing values, but retains
phase names/order, selections, reasons, obligations, ambiguities, truncation,
counts, and estimates. The two canonical normalized JSON byte sequences must
match.

Latency percentiles use nearest-rank over the 15 cold task runs. Phase timing
uses monotonic elapsed milliseconds. Timing values are evidence, not replay
identity.

## Technical gates

All of the following must pass:

1. Changed-hunk enclosing-symbol coverage: target 100%.
2. Provisional required-context recall: target at least 90%.
3. Median token reduction versus arm B: target at least 3.0x.
4. Compilation p50: target below 2 seconds.
5. Compilation p95: target below 5 seconds.
6. Maximum individual phase: target at most 1 second on repositories with no
   more than 10,000 target-language code files, absent a preregistered
   justification (none is preregistered).
7. Unreviewed sensitive upload: target zero.
8. Share Format changes: target zero.
9. CLI expressibility: target 100% through existing selection strings.
10. Existing validator success: target 100% for generated Shares.
11. Exact normalized replay: target 15 of 15.
12. Runtime LLM, embedding, index, AST, or network dependency: target zero.

## Decision rule

`TECHNICAL_GO_HUMAN_PENDING` requires every technical gate to pass.

`REVISE` applies when recall is 80-90%, median reduction is 2.0-3.0x, or one
candidate channel has a material but isolated failure. Exactly one targeted
channel correction and one rerun on the same frozen tasks are allowed.

`KILL` applies when recall is below 80%, median reduction is below 2.0x, there
is any unreviewed sensitive disclosure, a new capture path or Share Format
change is required, p95 exceeds 10 seconds below 10,000 target-language files,
reliable operation requires semantic indexing or an LLM, or completion
requires materially expanding this frozen scope.

`BLOCKED` is reserved for an external prerequisite that prevents honest
scoring.

## Human gate

Technical passage does not establish product acceptance. The observation
package asks five genuine developers to review ten genuine changes and measures
at least 70% proposed-item retention, less than 15% substantial context
addback, time saved for at least four of five developers, zero publication of
material a participant did not understand, and whether participants rechecked
the full change. These observations remain pending and may not be simulated.
